# DPT.DOOM 2 — техническое задание

Порт DPT.DOOM на C#. Идеи берутся из первого DPT.DOOM (C/DoomGeneric), кодовая
база — Managed Doom (C#-перевод Linux Doom). Репозиторий называется `DPTDOOM2`,
публичное имя продукта — **DPT.DOOM**, бинарник — `dptdoom.exe`.

## 1. Платформа

- **.NET Framework 4.0** — основная цель, чтобы работало на **Windows XP SP3**.
  `net9.0` существует только для запуска тестов на современном SDK.
- Не использовать API, которых нет в 4.0: `Span<T>`, `MathF`, `HashCode`,
  `record`, `Math.Clamp`, `IReadOnlyList`, `Dictionary.TryAdd`,
  `ExceptionDispatchInfo`. Замены — `DPTDOOM/src/Common/Compat.cs`.
- Windows — основная и единственная проверенная платформа. Бэкенды изолированы
  интерфейсами, чтобы другие ОС можно было добавить позже.

## 2. Standalone: без сторонних библиотек

Цель — **ноль внешних зависимостей** в поставке. Только код проекта и системные
DLL Windows.

Уже сделано: удалены Silk.NET, TrippyGL, DrippyAL, MeltySynth, GLFW,
OpenAL Soft. Взамен:

- окно и вывод кадра — `user32` + `gdi32` (`StretchDIBits`);
- звук — `winmm` `waveOut` и свой программный микшер;
- музыка — MUS → MIDI через системный синтезатор (`winmm` `midiOut`);
- ввод — сообщения окна.

Новую функциональность писать так же: сначала системный API, потом своя
реализация. Не подключать NuGet-пакеты в поставляемые проекты
(`DPTDOOM`, `DPTDOOM.Shared`, `DPTDOOM.Master`, `DPTDOOM.Launcher`).
`Microsoft.NETFramework.ReferenceAssemblies` — исключение: это reference
assemblies для компиляции, не рантайм.

## 3. Функциональность

### 3.1 Игра

Демо-совместимый порт: физика, монстры, оружие, двери/лифты, секреты,
сохранения, демо, DeHackEd, automap, интермиссия, финалы. Хеши состояния мира
должны совпадать с эталонами Managed Doom — это проверяется тестами.

### 3.2 Headless

Режим без окна, звука и ввода — для автоматических тестов, бенчмарков и снятия
кадров:

```
dptdoom -headless -iwad doom2.wad -warp 1 -tics 70 -shot frame.bmp
```

Печатает хеши мира (`State: mobj=... sector=...`). Headless — тестовый бэкенд,
**не** dedicated server.

### 3.3 Кооператив

Lockstep по TCP, 2–4 игрока, состояние мира не передаётся — только `TicCmd`.
Сверка digest WAD перед стартом. Подробности: `docs/NETWORK.md`.

Не заявлять как Internet-ready: нет шифрования, NAT traversal, reconnect,
late join, сохранений в сети.

### 3.4 Master server

Нативный сервер списка сессий (directory). Не игровой сервер. Протокол v1,
ban/allow-списки, lease с токеном. Подробности: `docs/MASTER.md`.

Relay через master объявлен в протоколе (операции 5/6), но **не реализован**.

### 3.5 Лаунчер

HTML/CSS/JS внутри EXE. Рендер — **MSHTML** (`WebBrowser`), потому что WebView2
на Windows XP не устанавливается, а MSHTML есть всегда и не требует рантайма.

- Мост страница↔C# — навигация на `dptdoom://<verb>`, которую хост отменяет и
  разбирает. COM (`window.external`) не используется: на части систем он молча
  не отдаёт методы.
- Страница под старый движок: ES5, без CSS-переменных, `grid`, `flex`,
  разметка только `div`.
- Профили, темы (светлая/тёмная), браузер серверов, предпросмотр аргументов,
  лог сессии, portable-режим.

Подробности: `docs/LAUNCHER.md`.

ANOM_Style, IWAD. Всё это в `.gitignore`, в репозиторий не идёт.

## 5. Средний и долгий срок

- Relay через master, server browser с ping/избранным.
- Reconnect, late join, dedicated server.
- PK3/ZIP как контейнер ресурсов, включая WAD внутри.
- DeHackEd: расширить подмножество; BEX/MBF/MBF21 — только после аудита.
- DECORATE-подобные расширения (смотреть DOOM ACE).
- Боты для DM/COOP, умеющие проходить карты.
- 3D-полы, воксели, HD-текстуры, аппаратный рендер.
- Кроссплатформенные бэкенды на тех же интерфейсах.

## 6. Правила разработки

Полные правила — `AGENTS.md`. Кратко:

- Частые тесты — headless; оконную игру запускать после крупных изменений.
- Коммиты небольшие и логические, после проверок. Пушит владелец.
- Документацию и UI держать по-русски, код и комментарии — по-английски.
- Не коммитить IWAD, сохранения, логи и личные пути.
