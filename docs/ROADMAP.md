## 4. Сеть

- [x] Lockstep TCP host/join на 2–4 игроков.
- [x] Сверка digest WAD перед стартом.
- [x] Статус подключения шрифтом Doom.
- [x] Проверено: 1500 тиков, хеши мира у хоста и гостя совпадают.
- [x] Упреждение ввода: при 100 мс пинга 57 тиков/с вместо 17.5.
- [x] **Reconnect после обрыва.** Обе стороны замирают на одном и том же тике:
  lockstep не даёт уйти дальше, чем есть команды. Поэтому состояние мира
  передавать не нужно — достаточно дослать команды, потерянные вместе с
  соединением. Гость хранит последние 256 своих команд и повторяет их при
  возврате; хост повторяет свои и пересланные чужие. Слот не перевыдаётся:
  иначе вернувшийся получил бы чужие команды. Задержка ввода при возврате не
  пересчитывается — она сдвигает нумерацию тиков. Ожидание 30 с, потом сессия
  завершается с внятной причиной, как раньше.
  Проверки: `NetReconnectTest` (4 теста, хеш применённых команд обеих сторон
  сверяется потиково), `tools/test-reconnect.ps1` — реальный разрыв через
  прокси, хеши мира совпали на 4000 тиках.
- [ ] **Late join** - подключение к идущей игре.
- [ ] Dedicated server.
- [x] Relay через master: TCP-прокси, хост без проброса порта, NAT hairpin.
- [x] Чат в игре: `T` открывает строку, `Enter`/`Esc`, хост пересылает гостям.
- [ ] Голосовой чат.
- [x] `dmflags`: `-noblock` (игроки сквозь друг друга), дубли DM-оружия, общие ключи.
- [ ] Сессия с настраиваемым max игроков: 2–4 сейчас, предел движка. До 1024 —
      отдельный проект (массивы игроков, формат демо, интермиссия).

## 9. Совместимость и контент

- [x] DeHackEd (подмножество).
- [x] **PK3/ZIP как контейнер**: свой читатель ZIP (`ZipArchiveReader`) на
      `DeflateStream`, потому что `ZipArchive` появился только в .NET 4.5, а
      целевая платформа — 4.0 для XP. Внутри PK3 грузятся WAD (рекурсивно) и
      отдельные люмпы. Режим игры определяется по картам (`MAP01` / `E1M1`), а не
      по имени файла, иначе контейнер с произвольным именем не опознавался.
- [x] **PNG-графика из PK3**: свой декодер PNG (`PngImage`) — тоже без сторонних
      библиотек. Плоскости из `flats/*.png` декодируются, масштабируются в 64×64
      и переводятся в индексы PLAYPAL; плоская текстура из PK3 переопределяет
      одноимённую из IWAD.
- [x] **Текстуры стен и спрайты из PK3**: PNG переводится в формат патча Doom
      (`Pk3Graphics.ToPatch`) — колонки с «постами», прозрачность как отсутствие
      пикселя. `textures/NAME.png` заменяет одноимённую стену, `sprites/POSSA1.png`
      (или `POSS A1.png`) — спрайт, с якорем по центру нижней кромки.
- [ ] ZDoom `TEXTURES` — язык описания составных текстур. Сейчас поддерживается
      только простая форма «один PNG на текстуру».
- [ ] Interlaced PNG (Adam7): сейчас отвергается с внятной ошибкой.
- [ ] DECORATE-подобные расширения (смотреть DOOM ACE).
- [x] **Boom generalized linedefs**: декодер битового поля
      (`BoomGeneralized`) по спецификации из `refs/prboom-plus`, плюс обработка
      полов, потолков, дверей, запертых дверей, лифтов, лестниц и давилок.
      Триггеры (walk/switch/gun/push, одноразовые и повторяемые) разведены по
      трём путям активации.
- [ ] Boom: числовая модель смены текстуры (`ChgM`). Сейчас используется
      триггер-модель — текстура берётся у сектора линии. Числовая ищет по карте
      сектор нужной высоты; без неё текстура была бы неправильной, а это хуже,
      чем ванильная.
- [x] **Boom: перенос света 213/261.** Пол или потолок сектора освещается по
      другому сектору: хранится **индекс** управляющего сектора, а свет читается
      при отрисовке. Поэтому мерцающий управляющий сектор анимирует всё, что у него
      занимает свет — ровно то, ради чего специальность существует. Залитое в
      момент загрузки значение выглядело бы верно один кадр, а потом замерло.
      Ванильная отрисовка не изменилась: кадр совпал байт-в-байт.
      Тесты: `BoomLightTransferTest` (4 проверки, включая «свет читается вживую»).
- [ ] Boom/MBF: остальные именованные спецлинии (242 глубокое вещество, 209/210),

- [x] **Именованные линии Boom, часть 1**: 142–152, 155, 199–202, 212, 219/220,

- [x] **Именованные линии Boom, часть 4a: скроллеры** — 48/85 (стена вправо/влево),
      250/251 (потолок и пол по тегу линии), 252/253 (перенос вещей по полу),
      254 (стена по тегу), 255 (стена по своим смещениям). Скорость и направление

      Прокрутка плоскостей поддержана рендерером (смещение точки выборки, не
      геометрии) и **не входит** в хеш сектора — иначе все эталонные хеши

- [x] **Boom: флаги сектора + пушеры.** `SectorSpecials.EffectOf` снимает биты
      0x80/0x100/0x200 перед разбором эффекта — без этого карта с «нюкейдж + ветер»
      (0x207) теряла урон, потому что `switch` сравнивал всё 16-битное значение с 7.
      Ванильные карты не затронуты: все их значения меньше 32.
      Пушеры 224 (ветер) и 225 (течение) по правилам PrBoom: ветер толкает в воздухе
      полностью, на земле вдвое слабее; течение — наоборот, только на земле.
      Сила = вектор линии / 128 за тик (`PUSH_FACTOR = 7`).
      Тесты: `BoomPusherTest` (4 проверки).
- [ ] Boom, часть 4c: пушер 226 (точечный источник) — нужны вещи MT_PUSH/MT_PULL,

      специальность без них выглядела бы реализованной и не делала ничего.

## Идеи из первого DPT.DOOM

Перенесено из `refs/DPTDOOM-C/docs/IDEAS.md`; часть уже реализована.

- [x] Сохранение момента во время attract-демо (F2), загрузка как одиночная игра.
- [x] Headless для автоматических тестов.
- [x] Master server и лаунчер с браузером серверов.
- [x] Прямой кооператив (direct TCP lockstep).
- [ ] P2P-загрузка ресурсов: только PWAD и PK3, без коммерческих IWAD.
      Allowlist по хешам для Freedoom 1/2 и shareware DOOM1.WAD.

      и согласованным выполнением, не локальные читы, ломающие lockstep.
- [x] Стартовый экран: рамка, крупное состояние, детали под линейкой, полоса ожидания.
      Длинный заголовок ужимается, а не вылезает за рамку; причина отказа — по коду
      сокета, а не сырой текст исключения (шрифт Doom не имеет кириллицы).
- [ ] Общий и командный чат, цветные ники, cosmetic skins.
- [ ] Сохранение онлайн-снимка игры с предупреждением об отключении от сервера.
- [ ] Hairpin NAT: manual IPv4 / DNS / opt-in HTTPS API для публичного адреса.
- [ ] Duke Nukem 3D как источник идей: прицел, auto-run, инверсия мыши.
- [ ] Публикация артефактов сборки в GitHub Actions для тестировщиков.

## Известные ограничения

- Windows XP не проверен на живой машине.
- Сеть не Internet-ready: нет шифрования и аккаунтов. Relay снимает проблему
  проброса порта, но трафик идёт через master открытым текстом.
- Бот пока не проходит карты до конца.
- P2P-загрузка ресурсов не реализована.
