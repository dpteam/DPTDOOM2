# План и текущее состояние

Отметки: `[x]` — сделано и проверено, `[ ]` — не сделано.
Идеи перенесены из первого DPT.DOOM (C/DoomGeneric) и расширены.

## 1. Платформа и сборка

- [x] Порт Managed Doom (C#-перевод Linux Doom) в `DPTDOOM/`.
- [x] Целевая платформа **.NET Framework 4.0** (`net40`), `net9.0` только для тестов.
- [x] Полностью standalone: удалены Silk.NET, TrippyGL, DrippyAL, MeltySynth,
      GLFW, OpenAL Soft вместе с их лицензиями.
- [x] Свой Win32-бэкенд: `user32` + `gdi32` для окна и кадра.
- [x] Свой звук: `winmm` `waveOut` + программный микшер.
- [x] Своя музыка: MUS → MIDI через системный синтезатор.
- [x] Свой ввод: сообщения окна, без сторонних библиотек.
- [x] `src/Common/Compat.cs` — шимы для API, которых нет в net40.
- [x] Проверка `tools/check-standalone.ps1`: нет NuGet в поставляемых проектах,
      нет лишних DLL рядом с exe, цель действительно `net40`.
- [ ] **Реальный запуск на Windows XP** — код и API подобраны под XP, но
      проверки на живой машине не было.
- [ ] Кроссплатформенные бэкенды (SDL/X11) на тех же интерфейсах.

## 2. Движок

- [x] Программный рендерер: BSP, стены, полы/потолки, спрайты, свет, небо,
      fuzz, палитровые эффекты, интерполяция кадров.
- [x] Геймплей: физика, монстры, двери/лифты, оружие, секреты.

- [x] Демо-совместимость: хеши мира совпадают с эталонами (тесты).

### Плавность и тайминг

- [x] Исправлен порядок кадра: дробь интерполяции и флаг обновления считаются
      вместе (`FramePacer`). До этого кадры шли `1.000 → 0.500`, и картинка
      дёргалась каждый тик.
- [x] Вывод кадра через DIB-секцию + `BitBlt` вместо медленного `StretchDIBits`.
- [x] Клиентская область окна приводится к размеру кадра.
- [x] `FrameClock`: абсолютный дедлайн вместо `Sleep` остатка.
- [x] `-fpslog`: построчный лог интервала, рендера, вывода, ожидания.

- [x] Упреждение ввода: при 100 мс пинга 57 тиков/с вместо 17.5.
- [ ] **Reconnect** после обрыва.
- [ ] **Late join** — подключение к идущей игре.
- [ ] Dedicated server.
- [x] Relay через master: TCP-прокси, хост без проброса порта, NAT hairpin.
- [ ] Чат в игре (общий и командный).
- [ ] Голосовой чат.
- [x] `dmflags`: `-noblock` (игроки сквозь друг друга), дубли DM-оружия, общие ключи.

- [x] Стрельба с прицеливанием, проверка линии видимости и наличия патронов.

- [x] Рёбра порталов направленные: спрыгнуть вниз можно, залезть обратно — нет.

- [x] **Бот видит предметы** (`BotItemValue`): вид по имени спрайта.

- [x] Бот встаёт после смерти (жмёт Use на экране смерти).

## 9. Совместимость и контент

- [x] DeHackEd (подмножество).
- [x] **PK3/ZIP как контейнер**: свой читатель ZIP (`ZipArchiveReader`) на
      `DeflateStream`, потому что `ZipArchive` появился только в .NET 4.5, а
      целевая платформа — 4.0 для XP. Внутри PK3 грузятся WAD (рекурсивно) и
      отдельные люмпы. Режим игры определяется по картам (`MAP01` / `E1M1`), а не
      по имени файла, иначе контейнер с произвольным именем не опознавался.
- [x] **PNG-графика из PK3**: свой декодер PNG (`PngImage`) — тоже без сторонних
      библиотек. Плоскости из `flats/*.png` декодируются, масштабируются в 64×64
      и переводятся в индексы PLAYPAL; плоская текстура из PK3 переопределяет
      одноимённую из IWAD.
- [x] **Текстуры стен и спрайты из PK3**: PNG переводится в формат патча Doom
      (`Pk3Graphics.ToPatch`) — колонки с «постами», прозрачность как отсутствие
      пикселя. `textures/NAME.png` заменяет одноимённую стену, `sprites/POSSA1.png`
      (или `POSS A1.png`) — спрайт, с якорем по центру нижней кромки.
- [ ] ZDoom `TEXTURES` — язык описания составных текстур. Сейчас поддерживается
      только простая форма «один PNG на текстуру».
- [ ] Interlaced PNG (Adam7): сейчас отвергается с внятной ошибкой.
- [ ] DECORATE-подобные расширения (смотреть DOOM ACE).
- [x] **Boom generalized linedefs**: декодер битового поля
      (`BoomGeneralized`) по спецификации из `refs/prboom-plus`, плюс обработка
      полов, потолков, дверей, запертых дверей, лифтов, лестниц и давилок.
      Триггеры (walk/switch/gun/push, одноразовые и повторяемые) разведены по
      трём путям активации.
- [ ] Boom: числовая модель смены текстуры (`ChgM`). Сейчас используется
      триггер-модель — текстура берётся у сектора линии. Числовая ищет по карте
      сектор нужной высоты; без неё текстура была бы неправильной, а это хуже,
      чем ванильная.
- [ ] Boom/MBF: остальные именованные спецлинии (242, 213, 100–105 и прочие),
      помимо обобщённых.
- [x] **Именованные линии Boom, часть 1**: 142–152, 155, 199–202, 212, 219/220,
      256/257 — полы, потолки, лифты, лестницы, donut, переключатель пола.

- [x] **Именованные линии Boom, часть 2**: 153/154 и 239/240 (смена текстуры и

## Известные ограничения

- Windows XP не проверен на живой машине.
- Сеть не Internet-ready: нет шифрования и аккаунтов. Relay снимает проблему
  проброса порта, но трафик идёт через master открытым текстом.
- Бот пока не проходит карты до конца.
- P2P-загрузка ресурсов не реализована.
