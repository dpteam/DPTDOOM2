# dptdoom.pk3 — архив, который движок делает сам

```
dptdoom-data/
├── dptdoom.pk3          ← артефакт сборки: перезаписывается, когда меняется таблица
└── actors/              ← то, что правит человек: никогда не перезаписывается
    ├── monsters.dpts
    ├── items.dpts
    ├── decorations.dpts
    └── README.txt
```

## Зачем два места

Это первая половина того, что ZDoom делает с `zdoom.pk3`: собственный контент движка лежит
**архивом, который движок собирает себе сам**. Разница с тем портом намеренная и её стоит
назвать: там архив собирают **скрипты сборки**, которых у игрока нет. Здесь его собирает
движок при первом запуске и обновляет, когда отпечаток таблицы перестал совпадать.

Обе копии существуют потому, что у них разные задачи:

| | Папка `actors/` | `dptdoom.pk3` |
|---|---|---|
| для чего | её **правит человек** | **копируется на другую машину** одним файлом |
| перезапись | **никогда** | когда меняется отпечаток таблицы |
| приоритет | **выигрывает**, если есть | запасной вариант, если папки нет |

**Папка выигрывает, когда есть обе.** Правка — это решение; пересобранный артефакт — нет.
Поэтому архив может обновиться сколько угодно, не отменяя того, что человек изменил.

## Что внутри

| Путь в архиве | Что это |
|---|---|
| `actors/monsters.dpts` | монстры, значениями таблицы |
| `actors/items.dpts` | предметы |
| `actors/decorations.dpts` | декорации |
| `actors/README.txt` | описание и **отпечаток сборки** |

Отпечаток читается **из README внутри архива**, а не из отдельного маркера: архив обязан быть
той же справкой, что и папка, и два места не могут расходиться в том, из какой сборки они
взялись.

## Как архив пишется

Своим кодом (`src/Doom/Wad/Pk3Writer.cs`), потому что `ZipArchive` появился в .NET 4.5, а
поставка — 4.0 для Windows XP. `DeflateStream` есть с 2.0, так что сжатие — framework, а
контейнер наш.

По умолчанию записи **stored**, без сжатия: внутри несколько десятков килобайт текста, которые
читаются один раз при старте, а несжатая запись не может быть испорчена компрессором, которому
кто-то должен доверять. Сжатие есть (`Pk3Writer.Write(..., compress: true)`) на случай, когда
это перестанет быть верным.

Запись идёт **рядом** с местом назначения и переезжает на него в конце: прерванная запись не
оставит половину файла там, где лежал рабочий.

## Как это проверено

- `Pk3WriterTest` (7): читаем своим читателем и **чужим** — `System.IO.Compression.ZipFile`
  из тестового проекта. Второе важнее: два наших куска, согласные насчёт файла, доказывают, что
  они согласны, а не что файл является ZIP.
- `ActorArchiveTest` (5): архив пишется, несёт отпечаток, применяется, когда папки нет,
  **папка выигрывает**, когда есть обе, битый архив сообщается и игнорируется.
- `tools/test-pk3.ps1` (живой прогон): Windows открывает архив как ZIP, второй прогон **не
  перезаписывает** файл (сверяется время изменения), а каталог только с архивом даёт **тот же
  хеш мира**, что и каталог с папкой.

## Чего здесь пока нет

В архиве только таблица актёров. Остальное содержимое движка — DECORATE, SharpScript и
будущие форматы — пока живёт там, где лежало; перенос каждого из них сюда отдельная работа, и
делать её «на всякий случай» значило бы получить архив, половина которого никуда не грузится.
