# LOCKDEFS

Что нужно, чтобы открыть замок с номером, что при этом говорится и что играет.

```powershell
dptdoom.exe -iwad doom2.wad mod.wad             # лампа LOCKDEFS внутри PWAD находится сама
dptdoom.exe -iwad doom2.wad -lockdefs my.txt    # файл, пока его правишь
```

## Какие номера замков вообще бывают

Это главное, что нужно понять до чтения файла.

Номер замка приходит **из карты**. В этом движке единственное место, где он есть, — обобщённая
запертая дверь Boom (`GenLockedBase`, спецлиния `0x3800`–`0x3bff`), у которой номер ключа
зашит в саму линию. Нумерация — **Boom'овская**, из `refs/prboom-plus/prboom2/src/p_spec.h`:

| Номер | Что нужно |
|---|---|
| 0 | любой ключ |
| 1 | красный |
| 2 | синий |
| 3 | жёлтый |
| 4 | красный череп |
| 5 | синий череп |
| 6 | жёлтый череп |
| 7 | все ключи |

`LOCKDEFS` эти номера **переопределяет**: строка `lock 1 { bluecard }` означает «замок номер
один требует синюю карту», даже если Boom на номере 1 имел в виду красную. Файл главнее —
именно для этого он и существует.

Нумерация ZDoom (где 1 — синий ключ) относится к картам формата Hexen. Такие карты этот
движок не грузит, поэтому номера в файле здесь означают то, что означает карта, а не то, что
означал бы тот же номер в ZDoom.

## Что поддерживается

```text
lock 1
{
    message "You need the blue card, and the red one will not help"
    lockedsound oof
    any { bluecard blueskull }
}

lock 7
{
    anyred
    anyblue
    anyyellow
}
```

- `lock <номер> { ... }` — определение замка;
- имя ключа без блока — **своя группа**: каждый такой ключ нужен;
- `any { ... }` — **одна** группа: достаточно любого из перечисленных;
- `anyblue`, `anyyellow`, `anyred` — сокращение для «карта или череп этого цвета»;
- `message "..."` — что сказать при отказе; кавычки обязательны, если в строке есть пробелы;
- `lockedsound <имя>` — звук отказа, по имени из `Sfx` (`oof`, `noway`…), и он же проходит через
  `SNDINFO`;
- `clearlocks` (или `clear`) — убрать встроенные правила Boom;
- `key = value` и `key value` равнозначны;
- комментарии `//` и `/* */`.

Ключи: `bluecard`, `yellowcard`, `redcard`, `blueskull`, `yellowskull`, `redskull`.

Форма «список групп, в каждой достаточно одного ключа» выбрана не для общности: она
**выражает все восемь случаев Boom без исключений**. Красная карта — одна группа из одного;
«карта или череп» — одна группа из двух; «все три ключа» — три группы по два; «все шесть» —
шесть групп по одному. Поэтому встроенные правила не пришлось переписывать отдельной веткой.

## Без файла

Встроенные правила Boom работают всегда, файл их только заменяет. Два места, где легко
ошибиться, и оба важны для автора карты:

- бит `LockedNKeys` — **не число ключей**, а «череп считается картой». С ним красный череп
  открывает красную карту, а «все ключи» означают по одному ключу каждого цвета вместо шести;
- отказ говорит **разное**: «нужна красная карта», когда тип важен, и «нужен красный ключ»,
  когда всё равно.

## Что не поддерживается

| Директива | Почему |
|---|---|
| `remotemessage` | в движке одна строка — тому, кто тронул дверь; другим не сообщается ничего, и второй строке негде появиться |
| `mapcolor` | автомапа рисует все линии одним цветом, цвет замка был бы принят и никогда не виден |

Обе **называются в отчёте загрузки**, а не проглатываются: принять `mapcolor` молча значит
сказать моддеру, что его цвет работает.

## `clearlocks` и замок без определения

`clearlocks` убирает встроенные правила. Если после него номер не определён, **дверь
открывается любому**, и загрузка говорит об этом одной строкой.

Так решено намеренно: отказ сделал бы дверь непроходимой **навсегда**, а это хуже, чем дверь
без замка. Но и молчать нельзя — «замок, которому ничего не нужно» это ровно та ошибка, ради
которой весь этот класс и написан.

## Ошибки, которые не роняют игру

| Что случилось | Что видно |
|---|---|
| неизвестный ключ | в отчёте имя; остальные ключи замка читаются |
| неизвестный звук | в отчёте имя; остаётся `oof` |
| номер вне диапазона | в отчёте; замок не добавляется |
| блок не закрыт | в отчёте; замок сохраняется |
| замок без ключей | в отчёте «открывается любому»; замок сохраняется |

Один плохой замок стоит себя: остальные определения файла применяются, уровень грузится.

## Почему это не ломает сеть

Какие ключи нужны — читается из контента при загрузке, одинаково на всех концах, потому что
контент у них один. Само решение «дверь открылась» — обычная симуляция: оно едет в мире, а не
в таблице. Демо, записанное с этим файлом, воспроизводится только с ним же — как и любое демо
с модом.

- `LockDefsTest` (23): разбор, кавычки в сообщении, `=` между ключом и значением, все имена
  ключей, `any`, `anyblue`, `clearlocks`, номера вне диапазона, незакрытый блок, оба вида
  комментариев, повторное чтение не удваивает, `mapcolor` пропускает **три** числа (иначе
  `0` и `0` читаются как имена ключей).
- `GeneralizedLockTest` (12): вся матрица Boom плюс то, что файл главнее встроенного правила.
- `BoomLockedDoorTest` (6): на настоящем MAP01 дверь не начинается без ключа и начинается с
  ним, череп без бита не подходит, с битом подходит, монстр не открывает, а лампа `LOCKDEFS`
  в PWAD меняет требуемый ключ.
- `tools/test-lockdefs.ps1` (живой прогон): лампа находится без ключа, чистый IWAD молчит,
  неподдерживаемые директивы названы, `clearlocks` принят, уровень грузится во всех случаях.
