# SharpScript

Свой язык для описания актёров. Не перенос DECORATE, а следующий шаг: та же логика
(актор, состояния, флаги), но записанная как код, а не как текстовый формат со своей
грамматикой.

Расширение файла — `.dpts`, ключ — `-script`, лампа в WAD — `SCRIPTS`.

```powershell
dptdoom.exe -iwad doom2.wad mod.dpts          # по расширению
dptdoom.exe -iwad doom2.wad -script mod.dpts  # явно
```

Лампа `SCRIPTS` читается автоматически: мод, которому нужны инструкции, — это мод,
который половина скачавших запустит неправильно.

DECORATE не интерпретируется отдельно: он **конвертируется в этот язык** и дальше идёт тем
же путём. Что переносится и что нет — `docs/DECORATE.md`.

## Зачем свой язык, а не встроенный C#

Три причины, и каждая сама по себе достаточна:

1. **Изоляция.** Любой встраиваемый C# требует рантайма, а рантайм — это ровно то,
   чего не должно быть у скачанного PWAD. Roslyn — сторонняя библиотека, а проект
   поставляется одной сборкой без сторонних DLL. `CodeDom` на XP нет.
2. **Детерминизм.** Скрипт исполняется до построения мира, на всех машинах, и обязан
   дать одинаковый результат. Свой язык даёт это по построению: нет часов, нет
   генератора случайных чисел, нет состояния между вызовами.
3. **Песочница как свойство грамматики, а не список запретов.** В языке нет выражения,
   которым можно назвать тип: точка — синтаксическая ошибка, а не «заблокированный
   член». Список запрещённых вызовов не нужно поддерживать в согласии с BCL, потому
   что пути к BCL нет вовсе.

## Язык

Маленький и намеренно скучный. Функции — единственная конструкция верхнего уровня.

```text
fn Thing_3004() {
    Health(Health() * 2);       // 20 -> 40
}

fn Thing_3001() {
    Speed(13);
    Flag("CountKill", false);
    DeathState("SkelDie1");
    Height(41.5);
}
```

### Имена актёров

`Thing_<DoomEdNum>`: `Thing_3004` — зомбимен, `Thing_3001` — имп. Именно DoomEdNum,
а не «Zombieman», потому что это единственный идентификатор, который уже есть везде:
в формате карты, в каждом редакторе и в таблице актёров. Имена вида «Imp» — изобретение
ZDoom, и второй словарь заставил бы каждого моддера помнить, какое из двух имён где.

Функция, чьё имя не начинается с `Thing_`, — **помощник**, и это нормально: так
скрипт делит арифметику между двумя актёрами.

```text
fn Double(n) { return n * 2; }
fn Thing_3004() { Health(Double(Health())); }
```

### Значения и типы

| Тип | Литерал | Арифметика |
|---|---|---|
| число | `42`, `-1` | целочисленная, `/` усекает к нулю |
| fixed | `1.5`, `0.25` | движковая 16.16, `/` как в движке |
| да/нет | `true`, `false` | из чисел: ненулевое — истина |
| текст | `"a"` | `+` приклеивает справа, если слева текст |

Литерал с точкой — fixed-число: `1.5` означает полтора, и разбирается он **из цифр
целочисленной арифметикой**, а не через `double`. `0.1` в 16.16 — это 6554/65536, и
именно это значение посчитает движок; прогон через float даёт 6553 или 6555 в
зависимости от платформы, и моддер увидит расхождение там, где его не ждёт.

Смешение числа и fixed даёт fixed (число расширяется без потерь — это единственное
неявное преобразование). Обратно — только явно, через `ToInt`: это усечение, и оно
должно быть видно в тексте.

### Управление

`if` / `else`, `while`, `break`, `continue`, `return`, тернарный `? :`, `&&`, `||`
с коротким замыканием. Скобки обязательны: язык, где `if x > 1` работает, а `if (x > 1)`
нет, читается хуже, чем язык, где обязательны обе.

Комментарии — `//`, `--` и `/* */`. Обе однострочные формы, потому что человек,
пишущий C#, тянется к первой, а человек, пишущий DECORATE или Lua, — ко второй.

### Область видимости

Переменные объявляются через `var` и живут до конца блока, в котором объявлены:

```text
fn Double(n) {          // n — параметр, область — тело функции
    var x = n * 2;      // x живёт до закрывающей скобки
    if (x > 10) {
        var y = 1;      // y живёт только внутри if
    }
    return x;
}
```

Три правила, и все три — про тихие ошибки:

- **Тень разрешена, повтор — нет.** `var x` во внутреннем блоке скрывает внешний `x`,
  это и есть смысл блока. А два `var x` в одном блоке — опечатка, и скрипт получит
  ошибку, а не «второй не имел эффекта».
- **Чтение необъявленного — ошибка в момент исполнения**, с номером строки. Не тихий
  ноль: ноль в определении здоровья выглядел бы как задумка автора.
- **`var` без инициализатора даёт `0`**, как в C. Это единственное место, где значение
  появляется само.

### Приоритет операторов

От слабого к сильному:

| Приоритет | Операторы |
|---|---|
| 1 | `=` `+=` `-=` (присваивание, правоассоциативное) |
| 2 | `? :` |
| 3 | `\|\|` |
| 4 | `&&` |
| 5 | `==` `!=` |
| 6 | `<` `<=` `>` `>=` |
| 7 | `+` `-` |
| 8 | `*` `/` `%` |
| 9 | `-` `!` (унарные) |

`&&` связывает сильнее `||`, поэтому `a || b && c` читается как `a || (b && c)`.
Скобки не запрещены и приветствуются там, где читателю пришлось бы вспоминать эту
таблицу.

Присваивание — выражение и возвращает присвоенное значение, поэтому
`return x = 5;` работает. Но `if (x = 5)` с одной `=` тоже скомпилируется и всегда
истинно — пишите `==`.

## API

Свойство актёра — одна функция: без аргумента читает, с аргументом пишет. Это даёт
`Health(Health() * 2)` без отдельного словаря геттеров.

| Функция | Тип | Смысл |
|---|---|---|
| `Health`, `Speed`, `PainChance`, `ReactionTime`, `Mass`, `Damage` | число | свойства актёра |
| `Radius`, `Height` | fixed | размеры, в единицах карты |
| `SpawnState`, `SeeState`, `PainState`, `MeleeState`, `MissileState`, `DeathState`, `XdeathState`, `RaiseState` | текст | состояние по имени |
| `SeeSound`, `AttackSound`, `PainSound`, `DeathSound`, `ActiveSound` | текст | звук по имени |
| `Flag("Имя")` / `Flag("Имя", да/нет)` | да/нет | флаг по имени |
| `ToInt(значение)` | число | усечение fixed к нулю; единственное явное сужение |
| `ToFixed(значение)` | fixed | расширение; полезно, чтобы подчеркнуть намерение |
| `Fail("текст")` | — | прекратить этот скрипт с сообщением, с номером строки |
| `State("Имя", "SPRT", "A", тики, "A_Действие", "Следующий")` | номер | новый кадр; см. ниже |

`Fail` — единственный способ скрипта сказать, что что-то не так: исключений в языке
нет, а тихо сделать не то — худший из вариантов. Сообщение попадёт в отчёт о загрузке
вместе с файлом и строкой.

```text
fn Thing_3004() {
    if (Health() <= 0) {
        Fail("health must be positive");
    }
    Health(Health() * 2);
}
```

Состояния и звуки — **по имени**, а не числом: моддер знает `SkelDie1` и не знает, что
это индекс 428 в перечислении этого движка, а индексы в разных портах разные.

Флаги — по одному за вызов. `"Solid, Shootable"` — не имя, и скрипт, который так
написал, получит ошибку, а не оба флага.

Полный список имён состояний и звуков — это перечисления движка (`MobjState`, `Sfx`);
`Flag` принимает имена из `MobjFlags`. Регистр не важен: `SkelDie1` и `skeldie1` —
одно и то же, потому что запоминать регистр имени из чужого перечисления — лишняя
работа.

### Свои кадры: `State`

Актор может принести собственные кадры, а не только поменять свойства:

```text
fn Thing_3001() {
    State("See1", "TROO", "A", 3, "A_Look", "See2");
    State("See2", "TROO", "B", 3, "A_Chase", "See1");
    SeeState("See1");
}
```

- **Имя** — своё у этого актора: два актора могут оба иметь `See1` и не столкнуться.
- **Спрайт** — четыре буквы, как в WAD (`TROO`, `POSS`), а не имя из перечисления
  движка: перечисление названо по первому кадру, который его использует, и `POSS` в нём
  нет вовсе.
- **Кадр** — одна буква `A`..`Z`, затем `[`..`` ` `` для зеркального ряда; `+` перед
  буквой — полная яркость.
- **Действие** — по имени, с `A_` или без. Если действия у движка нет (`A_Jump`), это
  ошибка с перечислением того, что есть: молча оставить кадр без действия значит
  получить актора, который выглядит правильным и не работает.
- **Следующий** — имя кадра этого актора или имя состояния движка (`Goto See` так и
  возвращает управление ванильному состоянию). Пустая строка — стоп.

Ссылки разрешаются после того, как определение доработает целиком: цепочка называет
следующего до того, как он определён. Кадр, чей следующий не найден, остаётся
указывать на `Null` — актор исчезает на этом кадре, и это видно сразу; в отчёте
названы и кадр, и имя.

Состояния берутся из резерва в 1024 слота на запуск; когда он кончится, скрипт получит
ошибку. Подробности — `docs/DECORATE.md`.

## Посмотреть, что загрузилось

```
~scripts
```

печатает актёров, которых описали загруженные скрипты, с файлом и строкой, и все
проблемы. Это первый вопрос при «мой скрипт не работает»: загрузился ли он вообще и
какое имя актёра он нашёл.

## Откуда взять рабочего актёра: `dptdoom-data/actors`

Встроенная таблица актёров — это **текст на диске**, а не числа в коде. При первом запуске
игра выкладывает её как SharpScript:

```text
dptdoom-data/actors/monsters.dpts       (монстры)
dptdoom-data/actors/items.dpts          (предметы)
dptdoom-data/actors/decorations.dpts    (декорации)
dptdoom-data/actors/README.txt
```

Эти файлы **загружаются**, и загружаются **до DeHackEd**. Из этого следуют три вещи:

- правишь число в файле — игра меняется, пересобирать нечего;
- `.deh`-патч, загруженный рядом, всё равно главнее: он применяется после;
- удалил папку — на следующем запуске вернулись встроенные значения.

Порядок здесь не случайность, а весь смысл: текст, применённый **после** патча, выставил бы
все поля обратно и молча отменил патч. Поэтому папка применяется раньше
`DeHackEd.Initialize`, а скрипты мода — позже обоих.

Папка **никогда не перезаписывается**: смысл распаковки в том, что её можно править.
Отключить целиком (ни читать, ни писать) — `-nodata`.

Отпечаток в README — это сборка, которая файлы написала. Если он не совпадает с текущей,
игра говорит об этом при старте: значения могли устареть. Это не ошибка — держать старый
справочник это выбор, — но и молчать об этом нельзя. Отпечаток считается **до** применения
папки, иначе отредактированная папка объявляла бы устаревшей сама себя.

Актёров без номера на карте (сам игрок, трассеры, вспышки) в файлах нет: язык называет
актёра по номеру, а у них его нет. Их 19 из 137, их значения остаются в движке.

Битый актор стоит **своего актёра**, не файла и не игры: остальные функции применяются,
уровень грузится, отчёт называет файл и строку.
## Ошибки

Скрипт с ошибкой **не** рушит игру. Актёр сохраняет прежнее поведение, уровень
загружается, а отчёт о загрузке называет файл и строку:

```
scripts: Failed (1 problem(s))
Warning: script problem: 1 - that script is skipped, the actor keeps its old behaviour
  mixed.dpts: line 5: 'NoSuchFunction' is not a function
```

Это тот же выбор, что делает загрузчик контента для битого спрайта: одна ошибка в
одном моде не должна стоить игры. Остальные актёры из того же файла при этом
применяются — ошибка стоит своего актёра, не файла.

## Ограничения, каждая с причиной

- **Нет `fn` внутри `fn`.** Замыкания требуют захваченного окружения, а окружение,
  живущее дольше вызова, — это состояние, которое дизайн запрещает.
- **Нет классов, глобалов, включений.** Каждое тянет модель областей видимости, а
  модель областей видимости — время жизни. Скрипт здесь — чистая функция от аргументов
  и состояния хоста, и именно это свойство делает его безопасным внутри lockstep.
- **Нет случайности и часов.** Определения исполняются до построения мира и должны
  дать одно и то же на всех машинах. RNG движка принадлежит миру, которого ещё нет.
- **Бюджет 100000 шагов на вызов.** В языке есть `while`, а цикл внутри игрового цикла
  — это зависание с нарисованным окном. Бюджет превращает его в ошибку через мгновение.
- **Глубина 32 вызова.** Бюджет считается на вызов, поэтому цикл между функциями
  сбрасывал бы его на каждом входе; глубину ограничивает именно этот предел.
- **Повторное применение запрещено.** Всякое интересное определение — это
  «прочитать и записать», поэтому второй проход молча удвоил бы эффект.
