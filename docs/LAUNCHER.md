# Лаунчер

`dptdoom-launcher.exe` — локальный HTML-интерфейс в одном EXE. Никаких CDN,
Node.js, Python, WebView2 или HTTP-сервера.

## Почему MSHTML, а не WebView2

Оригинальный DPT.DOOM использовал WebView2. Для порта на .NET Framework 4.0 это
неподходяще:

- **WebView2 не устанавливается на Windows XP** — ни Evergreen, ни Fixed Version.
- Он требует скачивания рантайма и наличия Edge в системе.
- Это внешняя зависимость, а цель порта — полностью standalone.

Поэтому интерфейс рендерит `WebBrowser` — обёртка над **MSHTML** (`mshtml.dll`),
движком Internet Explorer. Он есть в каждой поддерживаемой версии Windows и не
требует ничего доустанавливать.

Цена решения: движок старый. Страница написана под него:

- ES5-скрипт: без стрелочных функций, шаблонных строк, `Promise`, `let/const`.
- CSS без custom properties, `grid`, `gap` и `flex`.
- Только `div`-разметка: HTML5-теги в старом документ-режиме не стилизуются.
- Документ-режим поднимается до IE11 через `FEATURE_BROWSER_EMULATION`
  (ключ на текущего пользователя, запись необязательна).

## Как страница общается с C#

COM-мост `window.external` на части конфигураций молча не отдаёт методы, поэтому
используется схема, работающая везде:

```
JS  -> host:  window.__dptOutbox = payload;
              location.href = "dptdoom://<verb>"
host:         Navigating -> e.Cancel = true;
              verb = url после схемы
              payload = InvokeScript("dptdoomTakePayload")
host -> JS:   InvokeScript("dptReceive", [verb, payload])
```

Переход всегда отменяется — это только перенос сообщения. Никакой навигации в
интернет не происходит.

### Команды

| Verb | Что делает |
|---|---|
| `ready` | страница загрузилась: хост отдаёт тему, состояние, статус, путь данных |
| `preview` | собрать аргументы запуска и показать их |
| `browse` | `exe` / `iwad` / `pwad` — диалог выбора файла |
| `launch` | запустить игру |
| `profile` | `load` / `save` / `select` — профили 1–3 |
| `themeSave` | сохранить выбор темы |
| `masterSave` | сохранить адрес master |
| `masterRefresh` | запросить список сессий |
| `openLog` | открыть лог последней сессии |

### Список серверов

Кроме имени, адреса, карты и TTL, лаунчер показывает **ping** до игрового порта
каждого хоста, сортирует список по нему и умеет фильтровать по имени или карте.

Ping — это время TCP-рукопожатия с игровым портом, а не ICMP: raw-сокет требует
прав администратора, а игра говорит по TCP. Зато это ровно тот round-trip, который
потом будет проходить тик: тот же путь, та же задержка.

Хост, который не ответил за секунду, показывается как `-- нет ответа` и уезжает в
конец списка: объявление, до которого нельзя дозвониться, — худший вариант, а не
лучший.

Зондирование безвредно: хост видит подключение без рукопожатия и закрывает его.
Это специально закреплено тестом `HostRobustnessTest` — раньше **любая** ошибка
рукопожатия гостя останавливала всю сессию, и один случайный HTTP-запрос убивал
игру у всех.

Фильтр работает по последнему полученному списку и не ходит к master заново.

### Брендинг

Имя и цвета проекта живут в одном месте — `DPTDOOM.Shared/Branding.cs`. Это общая
сборка, потому что имя нужно четырём программам (игра, лаунчер, мастер, консоль) и
четырём видам файлов (C#, встроенный HTML, CSS, ресурс версии). Форк, который меняет
название, иначе обязан поменять всё сразу, а забытые места всплывают на скриншоте в
отчёте об ошибке.

Страница лаунчера — HTML внутри MSHTML и C# не видит вовсе, поэтому подстановка идёт
**при сборке страницы в память** (`LauncherForm.Brand`): в `ui.html` и `theme.css`
стоят метки `__BRAND_NAME__`, `__BRAND_MARKED__`, `__BRAND_TITLE__`,
`__BRAND_TAGLINE__`, `__BRAND_PRIMARY__`, `__BRAND_DARK__`. Замены, а не CSS custom
properties: MSHTML на XP переменных не знает, и правило «без `var(--x)`» из
`AGENTS.md` остаётся в силе.

`__BRAND_MARKED__` — имя, разрезанное по первой точке, чтобы акцентный `<em>` в
`DPT<em>.</em>DOOM` продолжал работать; у имени без точки акцента просто нет.

Что намеренно **не** в `Branding`: имена exe (это имена сборок в csproj), иконки
(двоичные файлы) и текст лицензии (это юридический текст, а не оформление).

### Формат payload

Строки через `\n`, PWAD-список — через `\u001f`:

```
executable, iwad, map, skill, address, port, name,
flag bits, mode, pwads, profile slot, coop bots,
master, relay session, relay flag, players, host bots,
password
```

`flag bits`: 1 = без монстров, 2 = быстрые монстры, 4 = возрождение,
8 = deathmatch, 16 = игроки сквозь друг друга, 32 = DM-оружие в коопе,
64 = ключи у каждого свои. `mode`: 0 = одиночная, 1 = хост, 2 = подключение,
3 = боты. Все поля пишет `LauncherState.Encode()`, поэтому сохранение и загрузка
не расходятся.

Поля после `profile slot` необязательны: payload от старой сборки просто
заканчивается раньше, и каждое недостающее поле берёт значение по умолчанию.
`password` — последнее в списке по той же причине, по которой его нет в
`SessionSettings`: **предпросмотр командной строки его не показывает** (`-password
****`), потому что эта панель висит на экране при настройке игры, а с неё и
начинаются отчёты об ошибках. Настоящее значение уходит только в процесс.

Формат списка серверов (строки от `EncodeServers`, поля через `\t`):

```
name, address, port, map, skill, ttl, session id, relay flag, ping ms
```

`ping ms` — `-1`, если порт не ответил.

расходятся.

### Имена команд сравниваются без учёта регистра

Это не перестраховка, а необходимость. MSHTML приводит часть URI после схемы к
нижнему регистру, поэтому `dptdoom://masterRefresh` приходит в хост как
`masterrefresh`. Пока сравнение было регистрозависимым, **молча** игнорировались
все команды с большой буквой: `masterSave`, `masterRefresh`, `themeSave`,
`openLog`. Кнопка «Обновить» отправляла запрос в никуда, и строка состояния
навсегда оставалась на «Запрос к master…».

Неизвестная команда теперь пишется в лог, а не отбрасывается без следа.

## Журнал лаунчера

Рядом с настройками лежит `launcher.log` — обычный текст с временем:

```
2026-10-23 21:51:32.723  verb masterrefresh (payload 11 chars)
2026-10-23 21:51:33.401  master refresh requested: '127.0.0.1:1'
2026-10-23 21:51:33.402    parsed 127.0.0.1:1
2026-10-23 21:51:35.420    failed after 2000 ms: SocketException: ...
```

Пишется всё: каждая команда от страницы, разбор адреса, результат запроса к
master с временем и ошибки. Лаунчер — программа, у которой сбои невидимы: окно
стоит, строка состояния показывает что было, и посмотреть потом нечего. Поэтому
журнал есть.

Файл обрезается, когда перерастает 512 КБ.

## Master и проброс портов

Адрес по умолчанию — `play.dartpower.xyz:25135`. Если master не отвечает,
лаунчер говорит, что именно проверить:

| Что случилось | Текст |
|---|---|
| порт закрыт | «отклонил подключение. Похоже, сервер не запущен или порт закрыт» |
| нет ответа за 4 с | «не ответил за 4 с. Порт закрыт файрволом, или адрес неверный» |
| имя не находится | «Имя ... не находится в DNS» |
| сеть недоступна | «Сеть до ... недоступна» |

**Relay встроен в интерфейс.** В режиме «Хост» есть галочка «Хостить через
relay»: игра запускается с `-master` и `-relay`, хост нигде не открывает порт.
В режиме «Гость» есть поле «Relay-сессия» — 32 hex-символа, которые хост печатает
при старте. Если заполнены и адрес, и сессия, прямое подключение пробуется первым,
relay — запасной путь.

**Пароль сессии** — одно поле на оба режима, хранится в профиле. Хост берёт из него
требование, гость — ответ; пустое поле означает открытую игру. В предпросмотре
командной строки он показан как `-password ****`: панель висит на экране при
настройке игры, и с неё начинаются отчёты об ошибках. Это не шифрование — см.
`docs/NETWORK.md`.

Список серверов показывает `DIRECT` или `DIRECT + RELAY` по флагу из объявления.
Кнопка «Выбрать» переносит id сессии в поле, если relay доступен. Подробности и
ограничения — `docs/RELAY.md`.

## Правила кооператива

В разделе «Правила игры» три галочки, которые меняют симуляцию:

| Галочка | По умолчанию | Что делает |
|---|---|---|
| Игроки проходят друг сквозь друга | выкл | снимает блокировку между игроками |
| Оружие из дезматч-карт | выкл | спавнит дубли пушек с DM-карт |
| Ключи у каждого свои | выкл | отключает общие ключи |

Они передаются игре как `-noblock`, `-coopweapons`, `-nosharedkeys`. Хост
выбирает, гость получает то же самое через приветствие — иначе миры разошлись бы.

Рядом поле «Игроков вместе с хостом»: 2–4. Четыре — предел движка, а не
интерфейса; почему так, написано в `docs/NETWORK.md`.

## Данные

| Режим | Каталог |
|---|---|
| `portable.txt` рядом с EXE | `<exe>/user/` |
| иначе | `%LOCALAPPDATA%\DPTDOOM\` |

```
launcher.ini          тема, master, последнее состояние
profileN.ini          сохранённые профили 1..3
launcher.log          журнал: команды страницы, запросы к master, ошибки
webview/launcher.html собранная страница (перезаписывается при старте)
game/profileN/        конфиг и сохранения игры (-userdir)
sessions/<время>/game.log  лог запуска
```

Игра запускается напрямую (`Process.Start`), без shell, с постоянным рабочим
каталогом профиля.

## Запуск

```powershell
.\DPTDOOM.Launcher\bin\Release\net40\dptdoom-launcher.exe
```

`dptdoom.exe` ищется рядом с лаунчером, затем в `DPTDOOM/bin/Release/net40`.
Путь можно задать вручную в поле «Исполняемый файл».

## Отладка страницы

```powershell
# собрать HTML и открыть в браузере: интерфейс без хоста (кнопки не работают)
.\dptdoom-launcher.exe --dump-html launcher-preview.html

# диагностика документа
$env:DPTDOOM_LAUNCHER_DEBUG=1
.\dptdoom-launcher.exe
# -> %LOCALAPPDATA%\DPTDOOM\launcher-debug.txt, launcher-nav.txt
```

## Автотест

`tools/test-launcher.ps1` создаёт форму, дожидается загрузки страницы и
проверяет: мост отвечает, статус приходит из C#, тема переключается, режим
«Создать COOP» показывает сетевые поля, а аргументы запуска собирает C#.
