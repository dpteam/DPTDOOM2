# SNDINFO

Какой люмп играет звук по имени.

```powershell
dptdoom.exe -iwad doom2.wad mod.wad              # лампа SNDINFO внутри PWAD находится сама
dptdoom.exe -iwad doom2.wad -sndinfo my.txt      # файл, пока его правишь
```

## Зачем это нужно

Движок находит люмп звука по соглашению: `DS` плюс имя. Для IWAD это работает, а для мода
ломается на первом же звуке, названном иначе. SNDINFO и есть файл, который ломает соглашение.

Три формы — и все три покрывают то, что мод делает на самом деле:

```text
weapons/pistol        DSPISTOL              // имя играет люмп
$alias door/open      dsdoropn              // второе имя для того же звука
$random door/close { dsdorcls dsbdcls }     // одно имя, несколько люмпов
```

Имена — это **имена `Sfx` движка** (`pistol`, `doropn`, `dbcls`), потому что звук в движке
выбирается перечислением, а перечисление не растёт в рантайме. Та же стена, что у `MobjType`,
и тот же ответ: тип остаётся в коде, данные уезжают в текст.

То есть мод может дать **ванильному** звуку свою запись без единой строки кода. Завести
**новый** звук, которого в движке нет, — нельзя; для этого понадобился бы реестр вместо
перечисления.

## Несколько люмпов на одно имя

`$random` — это и есть причина, по которой SNDINFO вообще пишут: один шаг это шаг, четыре
шага это шаги. Вариант выбирается при воспроизведении обычным `Random`, **не** генератором
движка: какой шаг прозвучал — это подача, а не симуляция. Взять его из мирового генератора
значило бы сдвинуть мир на одно число и положить выбор звука в хеш мира — ровно та ошибка,
против которой написаны правила про чат и наклон вида.

Один вариант — обычный случай, и он генератор не трогает вовсе.

## Что не поддерживается

`$volume`, `$attenuation`, `$pitchshift`, `$ambient` — **называются в отчёте загрузки** и
игнорируются. Принять `$volume` молча значит сказать моддеру, что его звук тише, когда он
не тише.

Одна неподдерживаемая директива стоит себя: её аргументы пропускаются до конца строки, а
записи после неё читаются.

## Ошибки, которые не роняют игру

| Что случилось | Что видно |
|---|---|
| имя без люмпа | в отчёте строка и имя |
| `$alias` без двух имён | в отчёте строка |
| `$random` без списка или с пустым | в отчёте, звук игнорируется |
| список `$random` не закрыт | в отчёте |
| люмп, которого нет в WAD | в отчёте имя люмпа; звук не играет |
| `$alias a b` и `$alias b a` | цикл разрешается в «ничего», а не в зависание |

Последнее — не педантизм: без предела глубины разрешение алиасов крутилось бы вечно внутри
кадра, то есть было бы зависанием с нарисованным окном.

## Проверка

- `SoundInfoTest` (15): три формы, регистр, цепочка алиасов, цикл, отказы, комментарии обоих
  видов, замена более поздней записью.
- `tools/test-sndinfo.ps1` (живой прогон): `-soundtest` печатает `DSDOROPN -> DSDORCLS`,
  когда файл так сказал, и рендерит именно этот люмп; алиас разрешается; неподдерживаемая
  директива названа, а запись после неё применяется; отсутствующий люмп назван.

`soundtest` резолвит имя через SNDINFO так же, как игра: инструмент, который игнорировал бы
маппинг, рендерил бы люмп, которого игра не играет, и врал бы о единственном, что он должен
отвечать.
