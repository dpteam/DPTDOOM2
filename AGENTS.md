# DPT.DOOM: правила работы

## Требования владельца

- Основное ТЗ — `PROMPT.md`; прогресс — `docs/ROADMAP.md`.
- Общаться по-русски. Публичное имя — **DPT.DOOM**, репозиторий `DPTDOOM2`,
  бинарник — `dptdoom.exe`.
- Цель: **полностью standalone** сборка под **.NET Framework 4.0**, включая
  Windows XP. Никаких сторонних библиотек в поставке — только код проекта и
  системные API.
- Основная среда проверки — Windows. Не выдавать сборку под другие ОС за
  проверенную.
- Частые тесты — headless. После крупных изменений иногда запускать оконную игру
  и оставлять открытой, чтобы владелец увидел результат.
- Git: небольшие логические коммиты после проверок. **Не пушить** без отдельной
  команды. Не откатывать чужие изменения.

## Данные и лицензии

- `refs/` — локальные материалы (старый DPT.DOOM, csDoom, DOOM ACE, ANOM_Style,
  WAD). Весь каталог в `.gitignore`.
- Лицензионный IWAD владельца: `refs/iwads/doom2.wad`. Не коммитить IWAD,
  сохранения, логи и личные пути.
- Исключение: showcase PNG в `docs/images/` для README, снятые из кадрового
  буфера или окна лаунчера. Без рамок, рабочего стола и чужих окон.
- Сохранять GPL и copyright исходных авторов (id Software, Nobuaki Tanaka).
  Код из `refs/` не становится своим от того, что лежит рядом: сначала
  проверять происхождение и лицензию.

## Тесты

```powershell
dotnet build DPTDOOM.slnx -c Release
dotnet test DPTDOOMTest\DPTDOOMTest.csproj -c Release
powershell -NoProfile -File tools\check-standalone.ps1
powershell -NoProfile -File tools\test-master.ps1
powershell -NoProfile -File tools\test-launcher.ps1
```

- `net40` — поставляемая сборка. `net9.0` существует только чтобы гонять тесты
  на современном SDK. Не добавлять в net40 API, которых нет в 4.0.
- `tools/check-standalone.ps1` проверяет обещание «без сторонних библиотек»:
  нет `PackageReference` в поставляемых проектах, нет лишних DLL рядом с exe,
  цель действительно `net40`. Не отключать и не ослаблять эту проверку.
- `test-launcher.ps1` запускать через Windows PowerShell 5.1: он грузит сборку
  net40 с WinForms, которую PowerShell 7 не хостит.
- Тесты совместимости без IWAD помечаются `Inconclusive`, а не падают.
- Геймплейные тесты сравнивают хеши мира с эталонами Managed Doom. Не обновлять
  эталоны молча при расхождении — это признак регрессии.
- Headless — тестовый бэкенд, **не** dedicated server.
- Звук — свой микшер (`src/Audio/SoundMixer.cs`, `SoundPan.cs`) плюс `waveOut`.
  Проверяется офлайн через `-soundtest` и юнит-тестами. Панораму не ломать:
  в Doom **положительный** относительный угол = источник **слева**. Перегруз
  голосов должен ограничиваться, а не заворачиваться — накопление идёт в float.
- Плавность кадра: порядок «дробь интерполяции → обновление мира → рендер»
  задаётся только `FramePacer`. Дробь обязана расти внутри тика и сбрасываться
  только на кадре с `update`. Не считать её отдельно от флага обновления.
- Вывод кадра — через DIB-секцию и `BitBlt`/`StretchBlt`; `StretchDIBits`
  напрямую в окно был в разы медленнее. Клиентская область окна приводится к
  размеру кадра, иначе GDI масштабирует каждый кадр.
- P/Invoke: при `CharSet.Unicode` + `ExactSpelling = true` указывать `EntryPoint`
  с суффиксом `W` обязательно (`SendMessageW`, `DefWindowProcW`, `LoadIconW`).
  Без него рантайм ищет функцию без суффикса и падает в рантайме, а не при
  сборке. Это ловит `PInvokeDeclarationTest` — не отключать.
- Иконка: только DIB-кадры в `.ico`, PNG внутри не понимает Windows XP.
  Пересборка — `tools/fix-icon.ps1`, проверка — `tools/test-icon.ps1`.
- Меню окна — `src/Win32/GameMenu.cs`, обработка команд — `Win32Doom.Execute`.
  Новый пункт добавлять в оба места и в `tools/test-menu.ps1`. Проверять
  галочки через `UpdateMenuChecks`, а не выставлять их вручную.
- Отладочные переключатели — `DebugSettings`. Всё, что меняет симуляцию
  (заморозка, замедление), разрешено только в одиночной игре: демо или сеть
  разъедутся. Проверка — `DebugSettings.SimulationChangesAllowed`.
- Боты: навигация — граф **секторов**, не субсекторов (см. `docs/BOTS.md`).
  Рёбра направленные и фильтруются по высоте шага и просвету. Маршрут
  продвигается только по факту входа в следующий сектор.
- Крупные апдейты — ZIP через `tools/package-build.ps1`.
- CI: `.github/workflows/ci.yml`, описание — `docs/CI.md`.

## Архитектурные ограничения

- Бэкенды изолированы интерфейсами `IVideo`, `ISound`, `IMusic`, `IUserInput`.
  Win32-бэкенд основной; headless платформенно-нейтрален. Новый бэкенд
  добавляется реализацией этих интерфейсов, а не правками движка.
- Никаких `Span`, `MathF`, `HashCode`, `record`, `Math.Clamp`, `IReadOnlyList`
  в коде под net40 — для этого есть `src/Common/Compat.cs` и замены в движке.
- Лаунчер: интерфейс — HTML в `Assets/`, встроенный в EXE. Движок рендера —
  MSHTML (XP-совместимость), **не WebView2**. Мост — навигация `dptdoom://`,
  не COM: `window.external` на части систем не отдаёт методы.
- Страница под MSHTML: ES5, без CSS custom properties/`grid`/`flex`, разметка
  только `div`. Новые HTML5-теги ломают документ-режим.
- Master — только directory. Не называть его игровым сервером. Relay объявлен в
  протоколе, но не реализован: не изображать его рабочим.
- Сеть: lockstep, состояние мира не передаётся. Любое изменение, влияющее на
  детерминизм симуляции (RNG, порядок тиков, физика), ломает совместимость —
  проверять `-botinput` soak-тестом и хешами мира.
- Сохранения в сети не поддерживаются. Не добавлять заглушки, выглядящие
  рабочими.

## Стиль

- Комментарии и идентификаторы — по-английски, документация и UI — по-русски
  (кроме технических строк, команд и логов).
- Комментарий объясняет **почему**, а не что. Особенно там, где решение
  неочевидно (MSHTML вместо WebView2, отмена навигации как IPC, отказ от COM).
- Не оставлять мёртвый код и «временные» заглушки без пометки.
